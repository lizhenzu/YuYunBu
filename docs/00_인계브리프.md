## 1. 한 줄 요약

관리자가 문제를 출제하면 참여자 휴대폰에 **실시간으로 문제가 뜨고**, 제출한 답변이 **별도 전광판 화면에 풍선(버블)으로 즉시 시각화**되는 웹 앱. 같은 답변이 많을수록 풍선이 커진다.

## 4. 반드시 지켜야 할 설계 3가지

### ① 브로드캐스트 스로틀링 ⚠ 최우선
100명이 동시 제출하면 초당 100회 푸시가 되어 전광판 애니메이션이 깨진다.

```
제출 → 서버 인메모리 집계 즉시 갱신 + DB 비동기 저장
     → 변경분(delta)을 버퍼에 누적
     → BackgroundService가 300ms마다 1회만 board 그룹에 브로드캐스트
```
- 브로드캐스트는 **초당 3~4회로 고정**
- 클라이언트는 delta만 수신해 부분 갱신 (전체 재계산 금지)
- 변경분 없으면 전송 생략

### ② 풍선 크기 공식
선형 매핑 금지(1등이 화면을 다 잡아먹음). **제곱근 스케일** 사용.

```
r(w) = r_min + (r_max - r_min) × sqrt( (c(w) - c_min) / (c_max - c_min) )

r_min = 32px, r_max = 화면 짧은변의 18% (최대 160px)
c_max == c_min 이면 전부 (r_min + r_max) / 2
표시 상한 40개, 나머지는 "기타 N종" 소형 풍선
```
- 신규 단어: `scale 0 → 1.15 → 1.0` 팝 바운스 250ms
- 기존 단어: 반지름 보간 400ms `ease-out-back` + 숫자 뱃지 카운트업
- 레이아웃: d3-force (`forceCenter` + `forceCollide(r+6)`), 갱신 시 **좌표 유지한 채 alpha 0.3 재가열**

### ③ 한글 정규화 파이프라인
"세종대왕 / 세종 대왕 / 세종대왕님"이 따로 놀면 워드클라우드는 무의미하다.

```
① Trim + 다중공백 축약   ② 유니코드 NFC   ③ 특수문자·이모지 제거
④ 영문 소문자화          ⑤ 존칭·조사 접미 제거 (님/씨/은/는/이/가/을/를)
⑥ 공백제거본 2차 키 생성 ⑦ WordAliases 사전 치환
⑧ BannedWords 검사       ⑨ 편집거리 ≤1 병합 "제안"만 (자동 병합 금지)
```
`DisplayText`는 최초 등장 또는 최다 빈도 원문 표기를 사용.

## 5. SignalR Hub 계약

**Hub: `LiveHub` → `/hubs/live`**

그룹: `room:{code}:participants` / `room:{code}:board` / `room:{code}:admin`

**Client → Server**
| 메서드 | 파라미터 |
|---|---|
| `JoinRoom` | `code, role, participantToken?, nickname?` |
| `SubmitAnswer` | `questionId, payload` |
| `OpenQuestion` | `questionId` *(admin)* |
| `CloseQuestion` | `questionId` *(admin)* |
| `RemoveAnswer` | `answerId` *(admin)* |

**Server → Client**
| 이벤트 | 페이로드 | 대상 |
|---|---|---|
| `StateSnapshot` | 현재 문항 + 집계 | 신규 접속자 |
| `QuestionOpened` | `{ id, type, title, options, config }` | participants, board |
| `QuestionClosed` | `{ id, finalAggregate }` | 전체 |
| `AggregateUpdated` | `{ questionId, deltas[], totals }` | board, admin |
| `ParticipantCount` | `{ joined, answered }` | board, admin |
| `SubmissionAck` | `{ status, answerId }` | 제출 본인 |
| `AnswerRemoved` | `{ answerId, token }` | board |

## 6. 데이터 모델 (핵심 테이블)

```
Sessions 1──n Questions 1──n QuestionOptions
   │              │
   │              └──n Answers ──n AnswerTokens
   └──n Participants ──┘
WordAliases        BannedWords
```

- **Sessions**: `Id, Code(char6 UNIQUE), Title, OwnerUserId, Status, ActiveQuestionId, CreatedAt, ClosedAt`
- **Questions**: `Id, SessionId, Order, Type(1단답/2객관식/3척도/4자유서술), Title, ConfigJson, Status(0대기/1열림/2마감), OpenedAt, ClosedAt`
- **QuestionOptions**: `Id, QuestionId, Order, Text, IsCorrect, ImageUrl`
- **Participants**: `Id, SessionId, Token(UNIQUE), Nickname, JoinedAt, LastSeenAt, IsBlocked`
- **Answers**: `Id, QuestionId, ParticipantId, RawText, OptionIds, ScaleValue, IsRemoved, SubmittedAt` — **UNIQUE(QuestionId, ParticipantId)**
- **AnswerTokens**: `Id, AnswerId, QuestionId, NormalizedText, DisplayText` — 인덱스 `(QuestionId, NormalizedText)`
- **WordAliases**: `Id, SessionId(NULL=전역), FromText, ToText`
- **BannedWords**: `Id, Word, Severity(1마스킹/2차단)`

## 11. 주의사항

- **다중 인스턴스로 배포하지 말 것.** 집계가 인메모리라 깨진다. 확장이 필요하면 Redis Backplane + 분산 집계로 먼저 전환.
- **IIS/App Service에서 WebSocket 활성화 필수.** 안 하면 LongPolling으로 떨어져 지연이 커진다.
- 자유서술은 **모더레이션 승인 후 노출 모드**를 반드시 제공할 것 (행사 사고 방지).
- 참여 코드 무차별 대입 방어: 입장 시도 5회/분, 제출 10회/분 레이트리밋.
