# 07. 유년부와 같은 구조로 바꾸기 — ChallengeBible 방 지시서

- 작성: 2026-11-09 (유년부 방) · 받는 곳: ChallengeBible 방 (`C:\WorkSpace\ChallengeBible`)
- 부록: [08_공유표_정의.md](08_공유표_정의.md) — 유년부 운영 DB 에서 자동으로 뽑은 표 정의 (칸 · 형식 · 키)
- 상태: **결정 대기 2건(9장)** 이 정해지면 착수

ChallengeBible 은 아직 사용자가 없다. 기존 설계 · 표 · 코드는 **마음껏 바꾸거나 지워도 된다**. 기준은 유년부다.

---

## 1. 목적

회원가입 · 역할 · 가족팀 · 시상 기록 · 미션 기록 · 통독 기록을 **유년부와 표 구조까지 똑같이** 만든다.

- 유년부 로직이 바뀌면 그대로 옮겨 올 수 있게 한다.
- 유년부 데이터를 **변환 없이** 매일 새벽 ChallengeBible 의 "유년부 영역"에 덮어쓴다(overwrite).

## 2. 정해진 결정 (사용자, 2026-11-09)

| # | 결정 |
|---|---|
| 부서 | ChallengeBible 은 부서별 SaaS 를 유지한다. 공유 표는 유년부와 같고, **`TenantId` 한 칸만 더** 붙인다 |
| 소속 | 한 사람은 한 부서에만 속한다 |
| 로그인 | 유년부와 같다 — 로그인 칸 하나에 **아이디 또는 이메일**. 이메일은 가짜도 된다. 회원 표는 ASP.NET Identity (`Identity` 스키마) |
| 반 | 반(학년 · 반) 표는 가져가지 않는다. ChallengeBible 에는 반 배정 개념이 없다 |
| 사람 열쇠 | 모든 기록은 회원 번호가 아니라 **아이디(UserName)** 로 사람을 가리킨다 |
| 아이디 변경 | 아이디는 바꿀 수 없다. 예외: **플랫폼 관리자만** 바꿀 수 있고, 바꿀 때 그 사람의 기록도 함께 새 아이디로 고친다 |
| 가입 순서 | ChallengeBible 순서(가입 → 임시 부서 "처음 오신 분" → 부서 고르기)는 그대로 두고, **역할 정하기와 승인만** 유년부 것으로 바꾼다 |
| 가족팀 | 표 이름 · 칸은 유년부 그대로(`DM2_FamilyTeam` 등). ChallengeBible 가족팀 코드를 여기에 맞춘다 |
| 시상 | 시상 기록 전용 표(`DM2_TeamAward`). 시상 기록이 있는 팀은 **나가기 · 내보내기 · 역할 바꾸기가 무조건 막힌다**(켜기/끄기 스위치 없음). 시상을 안 하는 부서는 기록이 안 생겨서 저절로 안 잠긴다 |
| 점수 | 미션 기본 점수 · 인정 기간 · 횟수는 **모든 부서 동일(플랫폼 고정)**. 부서가 정하는 것은 **시상 기준 점수뿐**(가족팀 점수 단계 `DM2_FamilyMilestoneConfig`). → ADR 0010 · 0060 고치기 |
| 기본 점수 | 말씀 본인 1 + 부모 1(하루 최대 2) · 퀴즈 1(하루 1, 두 번 맞혀도 1) · 기도 본인 1 + 다른 사람 1(하루 최대 2) · 암송 주 1회 1 |
| 미션 기록 | `DM2_MissionActivity`(한 미션 = 한 줄, 점수 포함) + `DM2_QuizAttempt`(시도 기록). 콘텐츠 번호는 남기지 않는다(퀴즈 시도에만 문제 번호) |
| 통독 기록 | 회차 구조. `DM2_ReadingRound` · `DM2_ReadingVerse`(책 · 장 · 절) · `DM2_ReadingBookmark` |
| 유년부 원본 | 유년부 사람의 가입 · 역할 · 가족팀 · 미션 · 통독은 **유년부 사이트에서만** 한다. ChallengeBible 에서 유년부 영역에 한 것은 새벽에 덮어써져 사라진다(공지로 안내, 시스템으로 막지는 않음) |
| 전송 | 매일 새벽 1회. ChallengeBible 에 **인증된 받는 창구(API)** 를 만들고 유년부가 보낸다. DB 직접 연결은 하지 않는다 |
| 아이디 겹침 | 겹친 사람만 건너뛰고 관리자에게 알린다. 고칠 때는 **항상 ChallengeBible 쪽** 아이디를 바꾼다 |

### 3-1. 유년부에도 새로 만드는 통독 표 2개 (결정 Q29, 2026-11-09)

사용자 결정: **"장 읽음"과 "보던 위치(이어 읽기)"는 유년부와 ChallengeBible 이 항상 같은 기능을 가진다.** ChallengeBible 에 있는 기능을 유년부에도 추가하며, 표는 ChallengeBible 설계(`app.ChapterRead` · `app.ChapterProgress`)를 아이디 열쇠로 바꾼 것이다. 유년부 방이 먼저 만들고 유년부 운영 DB 에서 08 부록을 다시 뽑으므로, **08 이 새로 나오면 그 정의를 따른다** (아래는 미리 정한 모양).

`DM2_ReadingChapterRead` — 이 회차에 한 장을 읽었다
| 칸 | 형식 | 빈 값 |
|---|---|---|
| UserName | nvarchar(256) | 아니오 |
| RoundNo | int | 아니오 |
| BookId | tinyint | 아니오 |
| Chapter | smallint | 아니오 |
| ReadAt | datetime2(3) | 아니오 |
- PK (UserName, RoundNo, BookId, Chapter) · 외래키 (UserName, RoundNo) → `DM2_ReadingRound` · 색인 (UserName, ReadAt)

`DM2_ReadingChapterProgress` — 이 장에서 마지막으로 보던 절
| 칸 | 형식 | 빈 값 |
|---|---|---|
| UserName | nvarchar(256) | 아니오 |
| RoundNo | int | 아니오 |
| BookId | tinyint | 아니오 |
| Chapter | smallint | 아니오 |
| LastViewedVerse | smallint | 아니오 (1 이상) |
| UpdatedAt | datetime2(3) | 아니오 |
- PK (UserName, RoundNo, BookId, Chapter) · 외래키 (UserName, RoundNo) → `DM2_ReadingRound` · 색인 (UserName, UpdatedAt DESC) — "이어 읽기"가 최근 것부터 찾는다

유년부 옛 기록에는 이 둘이 없으므로 **빈 표로 시작**한다(장 읽음은 읽은 절이 장의 모든 절을 채우면 계산으로 알 수 있다). 유년부 `DM2_VerseKey` 같은 짝표는 ChallengeBible 에 필요 없다.

가져가지 않는 것: `PersonMaster_2026`(교적 · 생일 · 연락처), `ClassInfo_2026` 등 반 표, `DM2_VerseKey`(유년부 옛 절 번호 짝표), 옛 클릭 기록 표(`ClickHistoryFor*`), `UserBibleProgress` · `UserBookMark`(유년부에서는 새 표로 가는 통로 뷰일 뿐).

## 4. `TenantId` 를 붙이는 규칙 (중요)

유년부 행을 **번호까지 그대로** 넣어야 하므로, 다른 부서의 자동 번호와 부딪히지 않게 한다.

1. B · C · D 표에 `TenantId INT NOT NULL` 을 더한다.
2. **기본 키는 (`TenantId` + 유년부 기본 키)** 로 만든다. 예: `DM2_FamilyTeam` PK = (TenantId, FamilyTeamId), `DM2_MissionActivity` PK = (TenantId, ActivityId).
3. 자동 번호(IDENTITY) 칸은 그대로 둔다. 유년부 영역에 넣을 때만 `IDENTITY_INSERT` 로 유년부 번호를 그대로 넣는다. 다른 부서는 자동 번호를 쓴다. (기본 키에 TenantId 가 있어 번호가 같아도 부딪히지 않는다)
4. **유일 색인 · 외래키에도 앞에 `TenantId` 를 붙인다.** 예: `UX_DM2_FamilyTeam_AwardKey` (TenantId, AwardKey), `FK_DM2_FamilyMember_Team` (TenantId, FamilyTeamId) → `DM2_FamilyTeam`.
   - 예외: `UX_DM2_FamilyMember_UserName` (UserName) 은 한 사람 한 부서라 그대로 전역 유일이어도 된다.
5. 칸 이름 · 형식 · 빈 값 허용 · 검사 제약은 08 부록과 **한 글자도 다르지 않게** 한다(전송이 그대로 들어가야 하므로).
6. 다른 부서 간 침범은 기존 설계대로 RLS + 앱 전역 필터로 막는다(ADR 0007 · 0020). 통독 표 · Identity 표는 부서 필터 대상이 아니다.

## 7. 유년부 영역 받는 창구 (4단계 — 이 지시서로 표를 맞춘 뒤 만든다)

- 인증: 유년부만 아는 비밀 열쇠(헤더). 열쇠는 DB 나 설정에 두고 소스에 적지 않는다.
- 받는 단위: 3장의 표 묶음별로 **유년부 영역 전체 행**(유년부 DB 그대로의 칸).
- 처리: 한 트랜잭션에서 그 표의 `TenantId = 유년부` 행을 지우고 받은 행을 그대로 넣는다(번호 포함). 통독 · Identity 표는 "유년부 소속 사람(유년부 `DeptRoleUserAssoc` 에 있는 아이디)" 의 행만 바꾼다.
- 아이디 겹침: ChallengeBible 에 같은 아이디가 **다른 부서 사람**으로 있으면 그 사람의 행은 건너뛰고, 건너뛴 목록을 응답과 관리자 알림에 남긴다.
- 실패하면 아무것도 바꾸지 않고(전체 롤백) 실패를 돌려준다. 유년부는 다음 새벽에 다시 보낸다.
- 자세한 형식(JSON 모양 · 크기 나누기)은 4단계에서 유년부 방이 정해 따로 보낸다.

## 8. ChallengeBible 방 진행 순서

1. 9장의 결정 대기 2건을 사용자에게 확인한다.
2. 미커밋 작업(`tools/sql/family-team-port.sql`, `docs/design/가족팀-논리-설계서.md` 등)을 정리한다 — 이 지시서와 겹치는 가족팀 이관은 **이 지시서가 우선**.
3. ADR 을 고친다: 0010 · 0060(점수는 플랫폼 고정, 부서는 시상 기준만), 0027 · 0004 · 0050(계정 = Identity, 아이디 · 이메일 로그인), 0083 · 0084(가족팀 표), 0029 · 0039 ~ 0042(통독 표). 새 ADR: "유년부와 공유 표 구조".
4. 물리 설계(`docs/design/물리-설계.sql`)를 08 부록 + 4장 규칙으로 다시 쓴다. 5장의 표를 지운다.
5. 코드를 6장 로직에 맞춘다 (회원 · 역할 → 가족팀 · 시상 → 미션 → 통독 순).
6. 테스트: 기존 테스트 중 지운 표를 쓰던 것은 새 표 기준으로 고친다. 유년부 운영 데이터 모양의 시험 데이터(번호 포함)를 유년부 영역에 그대로 넣어 화면이 열리는지 확인한다.
7. 7장 받는 창구는 유년부 방에서 4단계 형식을 받은 뒤 만든다.

## 9. 결정 대기 (사용자에게 확인)

- ~~Q29. 장 읽음 표시 · 보던 위치~~ → **결정됨(2026-11-09): 유년부와 ChallengeBible 이 항상 같은 기능을 가진다. 유년부에도 추가한다** (3-1). 유년부 방이 새 표와 "이어 읽기" 화면을 만든 뒤 08 을 다시 뽑아 보낸다 — ChallengeBible 방은 3-1 의 모양대로 먼저 만들어 두어도 된다.
- **Q30. 비밀번호** → **결정됨(2026-11-09): 암호화된 비밀번호(`PasswordHash`, `SecurityStamp`)도 함께 보낸다.** 유년부 사람이 같은 비밀번호로 ChallengeBible 에 들어간다. 받는 창구의 인증 열쇠는 반드시 지킨다(노출되면 안 됨).
- **Q31. 사이트 관리자 역할(`Identity.UserRoles`)** — 유년부 관리자가 ChallengeBible 관리자가 되는 것을 허용할지. (사용자에게 확인 중)

## 10. 앞으로의 동기화 규칙

- 유년부에서 공유 표나 6장 로직을 바꾸면, 유년부 방이 **변경 메모**(무엇을 · 왜 · SQL · 바뀐 파일)를 `docs/challenge-bible/` 에 남기고 ChallengeBible 방에 전달한다.
- ChallengeBible 은 공유 표의 칸을 혼자 바꾸지 않는다. 바꿔야 하면 유년부에 먼저 반영한다(유년부가 원본).
