- 관련: 07 지시서 7장(개요) · 08 표 정의
- 정해진 것: 새벽 1회, 인증된 창구로 보냄, 유년부 영역만 overwrite, 아이디 겹침은 건너뛰고 알림, 실행은 **GitHub 예약 실행**(Q32)

## 1. 한눈에 보기

```
GitHub Actions (매일 04:00 한국 시간)
   │  POST  https://<유년부>/api/sync/run      (열쇠 ①)
   ▼
유년부 사이트 ── 표를 읽어 묶음으로 나눠 ──►  POST https://<ChallengeBible>/api/sync/yunyunbu/...   (열쇠 ②)
   │                                              │ 임시 자리에 쌓았다가
   │ ◄──────────── 결과(건수 · 건너뛴 사람) ───────┘ 마지막에 한 번에 바꿔치기
   ▼
GitHub 는 /api/sync/status 를 보다가 끝나면 성공 · 실패를 표시 (실패하면 빨간 표시 + 이메일)
```

## 3. 주고받는 모양

모든 요청은 HTTPS, 본문은 JSON(gzip 압축). 한 번의 전송 = 한 "세션".

### ① 시작 — `POST /api/sync/yunyunbu/begin`
```json
{ "runId": "2026-11-10T04:00:03+09:00", "tables": { "Identity.User": 189, "DM2_ReadingVerse": 131922, "...": 0 } }
```
받는 쪽은 `sessionId` 를 돌려주고, 이 세션 전용 임시 표를 만든다. (미리 알려 준 건수는 마지막에 맞춰 본다.)

### ② 묶음 — `POST /api/sync/yunyunbu/chunk`
```json
{ "sessionId": "…", "table": "DM2_MissionActivity", "seq": 3,
  "columns": ["ActivityId","UserName","MissionDate","MissionItem","Points","ReciteWeekStart","PerformedAt"],
  "rows": [ [1,"kim01","2026-11-09","Word.Me",1,null,"2026-11-09T21:02:26"], ... ] }
```
- 한 묶음 = 최대 **5,000줄**. `seq` 는 표마다 0부터. 같은 `seq` 를 다시 보내면 덮어쓴다(재시도 안전).
- 값 모양: 날짜 · 시각 = ISO 8601 문자열, 숫자 = 숫자, 빈 값 = `null`, `bit` = `true/false`, `uniqueidentifier`/`nvarchar` = 문자열. **모든 값은 DB 의 값 그대로**(변환 없음).

### ③ 끝 — `POST /api/sync/yunyunbu/commit`
```json
{ "sessionId": "…", "counts": { "Identity.User": 189, "DM2_ReadingVerse": 131922 } }
```
받는 쪽은 임시 표의 건수가 `begin` 과 `commit` 에 알린 건수와 모두 같을 때만 진행하고, **한 트랜잭션**으로 유년부 영역을 바꿔치기한다(07 의 7장 · 4장 규칙). 하나라도 틀리면 아무것도 바꾸지 않고 실패를 돌려준다.

### ④ 취소 — `POST /api/sync/yunyunbu/abort`  `{ "sessionId": "…" }`
임시 표를 지운다. 보내다 실패하면 유년부가 부른다. 30분 넘게 끝나지 않은 세션은 받는 쪽이 스스로 지운다.

### 결과 (commit 응답)
```json
{ "ok": true, "tenant": "yunyunbu", "applied": { "DM2_MissionActivity": 24469, "...": 0 },
  "skippedUsers": [ { "userName": "kim01", "reason": "ChallengeBible 의 다른 부서 계정과 아이디가 같음" } ],
  "durationMs": 41230 }
```
`skippedUsers` 가 비어 있지 않으면 받는 쪽이 관리자에게 알림을 남긴다(Q18). 건너뛴 사람의 미션 · 통독 · 팀 기록도 함께 건너뛴다.

## 4. 인증 · 안전

- **열쇠 ②(유년부 → ChallengeBible)**: 서버 설정 파일에만 둔다(저장소에 넣지 않는다). 요청마다 `X-Sync-Timestamp` 와 `X-Sync-Signature = HMAC-SHA256(열쇠, 시각 + 메서드 + 경로 + 본문 SHA-256)` 헤더를 붙이고, 받는 쪽은 **시각이 5분 넘게 어긋나면 거절**한다. 열쇠는 "유년부 영역" 하나에만 묶여 있어 다른 부서 기록을 바꿀 수 없다.
- **열쇠 ①(GitHub → 유년부)**: GitHub 비밀 저장소(Secrets)에 둔다. 유년부 서버 설정에 같은 값을 둔다. `run` 은 이 열쇠가 없으면 거절한다.
- **한 번에 하나만**: 유년부는 실행 중이면 새 실행을 거절한다(`409`).
- **너무 적으면 보내지 않는다**: 어떤 표든 지난 성공 건수의 **50% 미만**이면 유년부가 전송을 멈추고 실패로 알린다(빈 표로 ChallengeBible 의 유년부 영역을 지우는 사고 방지). 받는 쪽도 같은 검사를 한다.
- 유년부에서 쓰는 점검 표 `DM2_SyncLog`(실행 시각 · 결과 · 건수 · 오류 메시지)를 두어, 관리 화면이나 조회로 지난 실행을 볼 수 있게 한다.

## 5. 유년부 쪽 만들 것

1. `DM2_SyncLog` 표.
2. `POST /api/sync/run`(시작만 하고 `202` 로 바로 돌려줌, 실제 전송은 사이트 안에서 이어서 실행), `GET /api/sync/status`(마지막 실행 상태).
3. 읽어서 5,000줄씩 보내는 코드(표 목록 · 거르기 규칙은 2장 그대로).
4. 서버 설정 파일에 넣을 값(예): `Sync:Enabled`, `Sync:TargetUrl`, `Sync:TargetKey`, `Sync:TriggerKey`.
5. GitHub 예약 파일 `.github/workflows/nightly-sync.yml`:
   - `schedule: cron '0 19 * * *'` (UTC 19:00 = 한국 04:00, GitHub 예약은 몇 분 늦을 수 있다) + 수동 실행 버튼
   - `run` 을 호출하고 `status` 를 몇 분 동안 확인하다가, 실패 · 시간 초과면 작업을 실패로 끝낸다.
   - Secrets: `SYNC_TRIGGER_URL`, `SYNC_TRIGGER_KEY`.

## 6. ChallengeBible 방이 만들 것 (07 지시서 8장 7번)

- 위 `begin` · `chunk` · `commit` · `abort` 네 주소와 서명 검사, 임시 표, 바꿔치기(유년부 `TenantId` 행 삭제 후 삽입, 번호 포함 `IDENTITY_INSERT`), 겹친 아이디 건너뛰기와 관리자 알림.
- 주의: 1번 표(`Identity.User`)는 부서 칸이 없다. **유년부 계정 = 유년부 `DeptRoleUserAssoc` 에 있는 아이디**로 정의하고, 그 계정들만 덮어쓴다.

## 7. 처음 한 번은 사람이 확인한다

- 첫 실행은 자동 예약 전에 **GitHub 의 수동 실행**으로 한다. ChallengeBible 방이 받는 창구를 만든 뒤, 건수와 몇 사람의 기록을 눈으로 대조한 다음 예약을 켠다.
- 유년부 `Sync:Enabled` 가 꺼져 있으면 `run` 은 아무것도 보내지 않고 "꺼짐"을 돌려준다(예약만 먼저 만들어 둘 수 있다).
