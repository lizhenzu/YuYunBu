# 01. 개요와 사용자 · 권한

## 1. 이 사이트가 하는 일

잠실새내교회 유년부(초등 1~3학년 주일학교)의 **학생 · 교사 · 학부모가 함께 쓰는 교회 포털**이다. 핵심은 "아이들이 매일 말씀을 읽고 기도하며 점수를 모으면, 점수에 따라 선물을 받는" 신앙 생활 동기 부여 시스템이고, 그 주위에 주일학교 운영 도구(출석부, 교적, 공과, 주보, 공지)와 가족 신앙 콘텐츠(기도문, 설교, 찬양, 영어, 사진첩)가 붙어 있다.

## 2. 사용자 종류

사이트의 "사용자"는 **세 가지 정보가 겹쳐서** 정해진다. 새로 만들 때 가장 먼저 정리해야 할 부분이다.

### 2-1. 로그인 계정 (ASP.NET Identity)

- 표: `Identity.User` (206명), 역할 연결 `Identity.UserRoles`, 역할 `Identity.Role`
- 회원가입(`/Identity/Account/Register`) 입력: 성 · 이름 · 이메일 · 비밀번호
  - **로그인 아이디(UserName) = 이메일의 @ 앞부분**이다. 예: `kim@gmail.com` → `kim`
  - 가입하면 자동으로 `Basic` 역할이 붙는다.
  - 이메일 인증은 꺼져 있다(가입 즉시 로그인).
- 비밀번호 규칙이 사실상 없다. 길이 1자 이상, 숫자 · 대소문자 · 특수문자 요구 없음 (`Startup.cs`).
- 로그인은 이메일 또는 아이디로 한다. 로그인 쿠키는 **30일 유지**(브라우저를 닫아도 유지, 사용할수록 연장).
- 로그인하면 세션에 `UserName`, `UserId`, `UserFullName`(성+이름)을 넣는다.

### 2-2. 교회 사람 정보 (교적)

- 표: `PersonMaster_2026` — 사람 한 명당 한 줄(`PersonId`). 생년월일(양력/음력 `plusMins`), 성별, 전화, 주소, 학교, 성경 완독 횟수(`readBibleAllCount`), 생일 공개 여부(`birthDay_PublishYN`), 로그인 아이디(`UserName`).
- **계정과 사람은 `UserName`(로그인 아이디)으로 이어진다.** 계정 없이 사람만 있을 수도 있다(아직 가입 안 한 아이). 동기화 프로시저: `usp_SyncPersonMaster2026_UserName_FromIdentityUser`.
- 반 편성: `ClassInfo_2026` (PersonID → 학년 `ClassYear` · 반 `ClassBan`), 반 목록 `ClassMaster` (1학년 1~4반, 2학년 1~4반, 3학년 1~5반, 모두 13반), 담임 `ClassTeacherMap_2026`.
- 부서 · 직분: `DeptRoleUserAssoc` (UserId → 부서 코드 `DeptCode` + 직분 코드 `RoleCode`).
- 이 모두를 합친 뷰가 **`view_UserCompositeInfo_2026`** 이다. 화면 대부분이 사람 이름 · 반 · 직분을 이 뷰에서 읽는다.

### 2-4. 화면 유형 (A / T / P / C)

- 홈에서 사용자를 **A 전체보기 · T 교사 · P 학부모 · C 학생**으로 나눠 메뉴를 다르게 보여 주던 기능이 있다.
- 저장 표: `UserUiPreference` (로그인 전에는 브라우저 IP 키, 로그인하면 아이디로 승격). 메뉴 정책: `UiMenuPolicy` (메뉴 주소별 허용 유형, 예: `/Attendance/Index` = `AT`).
- **지금은 모든 사용자를 `A`(전체보기)로 고정**해 두었다 (`HomeController`: "모든 사용자에게 전체 메뉴 표시"). 유형 고르기 화면 `/Home/PickUserType` 은 남아 있다.

## 3. 권한 규칙

권한은 **역할(Role)** 과 **특정 계정 이름**이 섞여서 쓰인다. 화면마다 기준이 다르므로 아래 표를 기준으로 삼는다.

### 3-1. 역할 4가지

| 역할 | 누가 | 의미 |
|---|---|---|
| `SuperAdmin` | 최고 관리자 | 모든 관리 기능. 삭제 · 초기화 · 역할 지정 · 가장하기 |
| `Admin` | 관리 교사 | 퀴즈 작성, 선물 관리, 출석 통계, 접속 기록 등 |
| `Moderator` | 교사 | 출석부 · 교적 · 감사 포인트 입력 · 스토리 관리 등 "교사 대시보드" 기능 |
| `Basic` | **모든 회원** | 가입하면 자동으로 붙는다. 권한 판정에 쓰면 안 된다 |

앱이 처음 뜰 때 `ContextSeed` 가 역할 4개와 기본 계정 4개(`SuperAdmin`, `Admin`, `Moderator`, `Basic`)를 만든다. 기본 계정의 초기 비밀번호가 코드에 들어 있으므로 **운영에서는 반드시 바꿔야 한다** (07 문서).

### 3-2. 계정 이름 예외 — "Basic" 계정과 "SuperAdmin" 계정

코드 곳곳에 **역할이 아니라 로그인 아이디로** 권한을 주는 예외가 있다.

| 기준 | 쓰는 곳 | 판정 |
|---|---|---|
| **기도 관리자** (`PrayManagerHelper.IsPrayManager`) | 365 기도, 치유 기도, 수험생 기도, 부부 기도의 목록 · 수정 · 검증, 조회수 제외 | 로그인 아이디가 `Basic` 또는 `SuperAdmin` (역할 무시) |
| **부부 기도 새로 쓰기 · 365 참여자 보기** (`CanAddCouplePray`, `CanSeePrayParticipants`) | 부부 기도 등록, 365 기도 참여자 줄 · 참여자 화면 | `SuperAdmin` 역할 **또는** 아이디 `Basic` |
| **슈퍼 유저** (치유 · 수험생 기도 등록 · 삭제) | `HealingAndRestorationPray`, `EntranceExamPray` | `SuperAdmin` 역할 **또는** 아이디 `basic` |
| **정보 관리 메뉴 "A"** | 정보 관리 허브의 A 표시 줄, 접속 기록 보기 | `Admin` · `SuperAdmin` 역할 **또는** 아이디 `Basic` |
| **"SB"** | 방문자 통계 | `SuperAdmin` 역할 **또는** 아이디 `Basic` (Admin 역할 제외) |
| **5분 말씀 관리** (`/RhapsodyOfReality`) | 목록 · 수정 · 평문 보기 등 | `SuperAdmin` 역할 **또는** 아이디 `Basic` |
| **선물 관리** | 홈 선물 관리 링크, 생일 선물 가격 보기 | `Admin` · `SuperAdmin` 역할 **또는** 아이디 `Basic` |
| **통계 수치 보기** | 홈 카드의 조회수 · 오늘 참여자 수, 허브 버전 선택 클릭수 | 아이디 `Basic` · `SuperAdmin` (·`Admin` 계정) |
| **집계 제외** | 접속 기록, 조회수, 허브 클릭 | 아이디 `anonymous`, `SuperAdmin`, `Basic`, `Admin` 은 기록하지 않음 |

> 주의: `Roles.Basic` 은 일반 회원 역할이다. "Basic 사용자"라고 하면 거의 항상 **아이디가 `Basic` 인 한 계정**을 뜻한다. 예전에 역할로 판정해서 모든 회원이 관리자가 된 사고가 있었다.

### 3-3. 정보 관리 허브의 권한 표시

`/HumanResource/ManageUserInfo` (홈 오른쪽 위 사진 → "정보 관리")의 메뉴는 줄마다 권한 글자가 있다.

| 글자 | 보이는 사람 |
|---|---|
| `all` | 로그인한 모든 사람 |
| `A` | `Admin` · `SuperAdmin` 역할, 아이디 `Basic` |
| `S` | `SuperAdmin` 역할만 |
| `B` | 아이디 `Basic` 에게 추가로 (`SB` = SuperAdmin + Basic 계정) |

### 3-4. 교사(Staff) 권한

- `StaffRoles = "Admin,SuperAdmin,Moderator"` — 감사 포인트 입력(`DevotionPoints`), 스토리 영상 관리(`Story`), 교적부(`ChurchRecord`), 교사 대시보드(`/Admin/TeacherOnly`), 반편성표 출력에 쓴다.
- 출석부(`Attendance`)는 로그인만 하면 들어갈 수 있고, 장기 결석은 `Admin` · `SuperAdmin` 만 본다.

### 3-5. 가장하기 (Impersonate)

- `/UserRoles/ImpersonateUser?userId=...` (SuperAdmin 전용) — 관리자가 **다른 사용자의 로그인 상태로 바꿔** 그 사람 화면을 본다. 인증 쿠키를 그 사람으로 교체하고(브라우저를 닫으면 풀림) 세션 사용자 정보를 지운다. 세션 키 `ImpersonateUserId` 가 남아 있다.

### 3-6. 로그인 없이 쓰는 화면

홈(`/`), 성경 검색, 기도문 대부분(오늘의 기도 · 상세 · 좋아요), 가족 사진 콘테스트(가족명+PIN 쿠키 방식), 그림 투표, 실시간 투표 참가, 생일 선물 안내 문자 화면(`/Admin/SendBirthMessage`) 등은 로그인 없이 열린다. 365 기도문은 출판사 허락 전이라 **로그인한 회원에게만** 보인다(`Prayer365Config.StaffOnly = true`).
