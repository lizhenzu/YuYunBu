# 05. 데이터베이스

> 모든 표의 열 목록은 [09 부록 B](09_부록B_전체_DB표목록.md)에 있다. 이 문서는 **무엇이 핵심이고 어떻게 연결되는지**를 설명한다.
> 행 수는 2026-10-21 운영 DB 기준이다.

## 1. 개요

| 항목 | 값 |
|---|---|
| DBMS | SQL Server (호스팅 공유 DB, 호환 수준 130 미만 → EF `UseCompatibilityLevel(120)`) |
| 스키마 | `dbo`(업무 전부), `Identity`(로그인 계정), `fit`(운동 문서 — 유년부와 무관한 부가 기능) |
| 개수 | 표 291 · 뷰 30 · 저장 프로시저 50 · 외래 키 65 |
| 접속 | ① 서비스 계층 · EF: `appsettings.json` 의 `DefaultConnection` ② 예전 계층(`DataAccessModule`): **코드 안에 접속 문자열이 박혀 있다** (07 문서) |
| 운영 · 로컬 전환 | `ConstatsCommon.timeDifference16` 값(16 = 운영) — 예전 계층만 해당 |

### 설계상 특징 (새로 만들 때 꼭 알아야 할 것)
1. **외래 키가 거의 없다.** 65개 중 대부분은 Identity, 게시판, 운동(fit) 표다. 미션 기록 · 포인트 · 출석은 모두 이름 문자열로 연결된다.
2. **사람을 가리키는 키가 세 가지다.**
   - `UserName` (로그인 아이디, 문자열) — 미션 클릭 기록, 선물, 쪽지, 접속 기록
   - `UserId` (Identity GUID 문자열) — 성경 진도, 북마크, 완독 선물, 역할 연결
   - `PersonId` (정수, `PersonMaster_2026`) — 출석, 묵상 점수, 반 편성
   이 셋을 잇는 것이 뷰 `view_UserCompositeInfo_2026` 이다. 아이디를 바꾸면 `usp_SyncPersonMaster2026_UserName_FromIdentityUser` 로 맞춰야 한다.
3. **연도별 표 분리.** `PersonMaster_2025/2026`, `ClassInfo_2026`, `AttendanceCheck_2025/2026`, `ClickHistoryFor*_2025`, `TodayWordToRead_2025`, `WeeklyWordToRead_2025`, `QuestionData_2025`. 새해가 되면 표를 새로 만들고 코드의 표 이름(`_2026`)을 고친다. 일부 표는 `cYear` 열로도 나눈다.
4. **백업 표가 많다.** `*_bak_v1~v6`, `*_bak_날짜`, `_bak_*`, `*_delete`, `aaa`, `*_111`, `*_1234` 등 60개 이상. 콘텐츠를 고칠 때마다 SQL 스크립트가 백업 표를 만든다. 앱은 쓰지 않는다.
5. **PK 없는 표가 많다**(`ClickHistory*`, `PrayPhrase`, `TodayWordToRead`, `CodeData` …). `Id IDENTITY` 열은 있지만 기본 키로 지정되지 않았다.
6. **날짜 열 이름이 제각각**: `InsertDT/updateDT`, `CreatedAt/UpdatedAt`, `InsertDT/UpdateDT`, `ClickDate`, `ExposeDate`.
7. 예/아니오 값이 `bit` 와 `nvarchar(1)`('Y'/'N', '1'/'0') 로 섞여 있다.

### 점수 계산
- **하루 미션 점수** = DB 함수 `dbo.ufn_DM2_GetUserDailyPoints(UserName, 시작일, 종료일)` 이 위 4개 기록 표를 합산한다. 도전 성경말씀 · 선물 · 대시보드가 모두 이 함수를 쓴다.
- **통합 점수**(대시보드) = 미션 연간 점수 + 출석 × 1 + 세계관(제출 3 + 보너스 2) + 묵상 점수 + 전도 × 50.
- 미션은 **오늘 · 어제 · 그제**만 누를 수 있다(코드에서 검사).

## 11. 앱이 스스로 만드는 표

앱 시작 · 첫 호출 때 `IF OBJECT_ID(...) IS NULL CREATE TABLE` 로 만드는 표가 있다(예: `SiteDailyVisit`, 가족 사진 콘테스트, 일부 선물 팝업 · 설정 표). **운영 DB에 바로 붙으므로 새 버전을 띄우면 운영 DB 구조가 바뀔 수 있다.**

## 12. SQL 스크립트 관리 (`SQL/` 폴더)

- 106개. 대부분 콘텐츠 개편(기도문 v1~v7, 365 기도 등)과 표 추가 스크립트다.
- 규칙: **UTF-8(BOM 없음) + CRLF**, 첫머리에 한글 깨짐 검사(깨졌으면 `RETURN`), 바꾸기 전 백업 표 생성, 트랜잭션.
