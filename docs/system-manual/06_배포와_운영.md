# 06. 배포와 운영

## 1. 운영 환경

| 항목 | 내용 |
|---|---|
| 호스팅 | SmarterASP.NET (서버 `win8190.site4now.net`, Windows + IIS) |
| 사이트 | `bit2001-001-site4` (현재 운영) / `bit2001-001-site3` (예전 · 시험용) |
| 공개 주소 | `https://www.jamsilkids.com` — `jamsilkids.com` 은 www 로 자동 이동 |
| 임시 주소 | `bit2001-001-site4.dtempurl.com`, `bit2001-001-site3.atempurl.com` — 검색 엔진 차단(robots, `X-Robots-Tag`) |
| 실행 방식 | IIS InProcess (`AspNetCoreModuleV2`), 프레임워크 의존(.NET 9 런타임이 서버에 있어야 함), self-contained 아님 |
| DB | 같은 호스팅의 SQL Server 공유 DB |

### 주의: 실행 파일 이름
`web.config` 의 `processPath` 가 `.\YunYunBu2024.exe` 다. 프로젝트 이름은 YunYunBu2025 지만 **어셈블리 이름이 YunYunBu2024** 로 남아 있다. 어셈블리 이름을 바꾸면 `web.config` 도 같이 바꿔야 사이트가 뜬다.

## 3. 로컬 개발

1. .NET 9 SDK, Visual Studio 2022(17.12 이상) 또는 `dotnet` CLI.
2. `appsettings.json` 을 받아 프로젝트 폴더에 둔다.
3. `ConstatsCommon.timeDifference16` 값에 따라 예전 계층이 **운영 DB에 붙을 수 있다.** 로컬 DB 를 쓰려면 이 값과 `DataAccessModule` 을 확인한다.
4. 실행: `dotnet run` 또는 VS F5. 시작 때 `Program.cs` 가
   - 스레드풀 최소 64 설정
   - 역할 4개와 기본 계정 시드(`ContextSeed`)
   - 성경 표가 비면 채우기(`BibleDataSeeder`)
   - `SiteDailyVisit` 표 생성(`SiteVisitCounter.EnsureTable`)
   을 한다. **즉 로컬에서 띄워도 연결된 DB에 쓰기가 일어난다.**
5. 화면 확인은 휴대폰 너비(375px)를 기본으로 한다.

## 4. 빌드 · 배포

### 방법 A — Visual Studio 게시(지금 쓰는 방법)
1. 솔루션 탐색기 → 프로젝트 오른쪽 클릭 → 게시
2. 프로필 `bit2001-001-site4 - Web Deploy` 선택 → 게시
3. 끝나면 사이트가 자동으로 열린다.

### 방법 B — FTP
`bit2001-001-site4 - FTP` 프로필, 또는 `dotnet publish -c Release` 결과를 FTP 로 올린다. 실행 중인 DLL 이 잠겨 있으면 호스팅 제어판에서 사이트를 멈추거나 `app_offline.htm` 을 먼저 올린다.

### 배포 체크리스트
- [ ] 빌드 경고 · 오류 없음 (`dotnet build`)
- [ ] 바뀐 SQL 스크립트가 있으면 **배포 전에** 운영 DB에 실행(백업 표 먼저)
- [ ] `appsettings.json`, `DataProtectionKeys/`, `wwwroot/uploads` 등 **서버에만 있는 파일을 덮어쓰지 않기**
- [ ] 홈, 로그인, 도전 성경말씀, 선물 화면 확인
- [ ] Git 에 커밋 · 푸시 (`main`)

### 디스크 공간
개발 PC 의 C 드라이브가 꽉 차면 빌드가 실패한다. `bin`(약 240MB) · `obj`(약 200MB)는 지워도 다시 만들어진다.

## 5. Git

- 저장소: `https://github.com/lizhenzu/YuYunBu.git`, 브랜치 `main` 하나로 운영.
- 화면 · 코드 옆에 `*.bak_before_*` 같은 이전 파일이 많다. Git 에 들어간 것도 있다.

| 방문자 수가 많음 | `SiteVisitCounter` — 쿠키 없는 봇 · 앱 내 브라우저는 매번 새로 셈 |

## 8. 백업

- DB 백업은 호스팅 제어판 기능에 의존한다. 자동 백업 주기를 확인해 둘 것.
- 콘텐츠를 고칠 때는 SQL 스크립트가 `*_bak_*` 표를 만든다(되돌리기용).
- 업로드 파일(`wwwroot/uploads` 등)은 Git 에 없으므로 서버에서 정기적으로 내려받아 보관해야 한다.
