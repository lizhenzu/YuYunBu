# 미션 기록 · 통독 기록 통합 표 설계서 (초안)

- 작성: 2026-11-09 · 상태: **승인 대기** (표 구조를 정하는 문서 — 코드는 승인 뒤에 시작)
- 목적: 유년부(YunYunBu)와 ChallengeBible 이 **같은 표 구조**를 쓰고, 유년부 기록을 **변환 없이 그대로** ChallengeBible 에 전송한다.
- 원본: 유년부 사이트. 전송: 매일 새벽 1회, ChallengeBible 의 "유년부 영역"만 overwrite (ChallengeBible 은 인증된 받는 창구를 둔다).

## 2. 표 이름

가족팀 표(DM2_FamilyTeam 등)와 같이 `DM2_` 머리를 쓴다. ChallengeBible 은 같은 이름에 **부서 번호 칸(TenantId) 하나만 더** 붙는다.

## 3. 미션 기록

### DM2_MissionActivity — 누가 · 어느 날 · 무슨 미션
| 칸 | 형식 | 설명 |
|---|---|---|
| ActivityId | bigint 자동번호, PK | |
| UserName | nvarchar(256) | 아이디 |
| MissionDate | date | 미션 날짜 (한국 시간) |
| MissionItem | varchar(20) | `Word.Me` `Word.Parent` `Prayer.Me` `Prayer.Others` `Quiz.Correct` `Recite` |
| Points | int | 그때 받은 점수 (1) |
| ReciteWeekStart | date, 없을 수 있음 | 암송일 때만 — 그 주의 시작일 |
| PerformedAt | datetime2(3) | 언제 눌렀는지 |

- 중복 막기: (UserName, MissionDate, MissionItem) 유일 — 암송은 (UserName, ReciteWeekStart) 유일.
- 일별 · 시즌 합계는 **표로 저장하지 않고** 이 표에서 계산한다(뷰). ChallengeBible 이 빠른 순위를 위해 자체 합계 표를 두더라도 전송 대상이 아니다.

### DM2_QuizAttempt — 퀴즈 시도 기록
| 칸 | 형식 | 설명 |
|---|---|---|
| UserName | nvarchar(256) | 아이디 |
| MissionDate | date | 날짜 |
| QuestionId | int | 문제 번호 (퀴즈는 여기에만 번호를 남긴다) |
| AttemptNo | tinyint | 1, 2 … |
| AnswerText | nvarchar(400) | 고른 답 |
| CorrectAnswerText | nvarchar(400) | 정답 |
| IsCorrect | bit | 맞았는지 |
| AttemptedAt | datetime2(3) | |

- PK: (UserName, MissionDate, QuestionId, AttemptNo). 그날 한 번이라도 맞으면 `DM2_MissionActivity` 에 `Quiz.Correct` 1줄(1점).

## 4. 통독 기록

### DM2_ReadingRound — 회차
UserName · RoundNo · StartedAt · CompletedAt(없을 수 있음) · ClosedAt(없을 수 있음). 사람당 진행 중 회차는 하나.

### DM2_ReadingVerse — 읽은 절 (회차별)
UserName · RoundNo · BookId(tinyint 1~66) · Chapter · Verse · ReadAt. PK 는 앞 다섯 칸.

### DM2_ReadingBookmark — 책갈피
UserName · BookId · Chapter · Verse · CreatedAt.

- ChallengeBible 에만 있는 "장 읽음 표시 · 보던 위치" 표는 유년부에 같은 기록이 없어 **이번 통합에 넣지 않는다**(장 완독은 절 기록에서 계산). 필요하면 나중에 양쪽에 함께 추가한다.

## 6. 영향 범위 (바꿔야 하는 곳)

- DB 개체 약 36개: 점수 함수 5(ufn_DM2_GetUserYearPoint, ufn_UserAreaPoints*, ufn_GetUserClickHistory*), 저장 프로시저 약 22(usp_missions_Insert*, usp_copy_*, usp_Compare_*, 통독 진행 저장 등), 뷰 5(view_UserBibleProgress, view_Read_bible_Details, view_click_data_all_person, AllClickTables, vw_DM2_ActiveUsers) 외 순위 뷰 연쇄.
- 코드 파일 약 40개: Bible2Controller · BibleController · DailyMission2Service · ControleBible · ControlClickHistoryFor* · ControlWithdraw · CheckPointController 등.
- 두 덩어리로 나눠 진행한다: **3A 미션 기록**(말씀 · 기도 · 퀴즈 · 암송) → **3B 통독 기록**.

## 7. 안전 장치

- 운영 DB: 만들기 · 옮기기 SQL 은 **로컬 DB 에서 먼저 검증**하고, 운영은 조회로 전후 비교한다 (옛 점수 합 = 새 점수 합, 사람별 · 날짜별).
- 옛 표는 새 코드가 안정될 때까지 **지우지 않는다**.
- 각 덩어리마다: 새 표 만들기 + 옮기기 SQL → 코드 교체 → 사용자가 SQL 을 먼저 실행 → 배포 → 화면 확인.
- 점수 · 순위는 사용자가 매일 보는 화면이라, 옮긴 직후 **순위 화면의 상위 10명 점수가 옛 화면과 같은지** 사람 눈으로 확인한다.

## 8. ChallengeBible 에 전달할 것 (지시서 재료)

- 위 5개 표(`DM2_MissionActivity` `DM2_QuizAttempt` `DM2_ReadingRound` `DM2_ReadingVerse` `DM2_ReadingBookmark`)를 같은 이름 · 같은 칸으로 만들고 TenantId 하나만 추가. 기존 `app.Activity` 계열 표는 drop.
- 유년부 영역 전송 받는 창구(인증, 유년부 영역에만 overwrite).
- 기본 점수는 플랫폼 고정, 부서가 정하는 것은 시상 기준 점수뿐(ADR 0010 수정).
