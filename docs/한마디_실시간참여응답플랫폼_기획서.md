| 항목 | 내용 |

## 1. 개요

### 1.1 한 줄 정의
관리자가 문제를 출제하면 참여자 화면에 **실시간으로 문제가 뜨고**, 참여자가 제출한 답변이 **별도 전광판 화면에 즉시 시각화**되는 웹 기반 실시간 응답 플랫폼.

### 1.2 기획 배경
- 강의·워크숍·예배·워크아웃·회의 아이스브레이킹에서 "청중의 생각"을 즉시 모아 보여주고 싶은 니즈
- 기존 Mentimeter / Slido는 유료·해외 서비스이며 한글 단어 병합(띄어쓰기·조사 처리)이 약함
- 자체 구축 시 브랜딩·데이터 소유·오프라인 행사 대응이 자유로움

### 1.3 핵심 가치
| 가치 | 설명 |
|---|---|
| **즉시성** | 제출 → 전광판 반영까지 1초 이내 |
| **무마찰 참여** | 앱 설치·회원가입 없음. QR 또는 6자리 코드만으로 참여 |
| **시각적 임팩트** | 같은 답변이 많을수록 커지는 풍선(버블) 애니메이션 |
| **다양한 문항** | 단답형 / 객관식 / 척도 / 자유서술 4종 지원 |

## 2. 사용자 역할 및 화면 구성

### 2.1 3-Screen 모델

```
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│  ① 관리자 콘솔  │      │  ② 참여자 화면  │      │  ③ 전광판 화면  │
│   (PC/태블릿)   │      │    (모바일)     │      │  (빔프로젝터)   │
├─────────────────┤      ├─────────────────┤      ├─────────────────┤
│ 세션 생성       │      │ 코드/QR 입장    │      │ 풀스크린 시각화 │
│ 문항 관리       │─push→│ 대기 → 문제표시 │      │ 실시간 집계     │
│ 출제 / 마감     │      │ 응답 입력·제출  │─push→│ 풍선 성장 연출  │
│ 응답률 모니터   │      │ 제출 완료 대기  │      │ QR 코드 상시노출│
└─────────────────┘      └─────────────────┘      └─────────────────┘
         └──────────────── SignalR Hub ────────────────┘
```

### 2.2 역할별 정의

| 역할 | 인증 방식 | 접속 경로 | 주요 권한 |
|---|---|---|---|
| **관리자 (Host)** | ID/PW 로그인 | `/admin` | 세션·문항 CRUD, 출제/마감, 결과 내보내기 |
| **참여자 (Guest)** | 무로그인 (익명 토큰) | `/join` → `/play/{code}` | 응답 제출, 본인 응답 수정(마감 전) |
| **전광판 (Board)** | 무인증 (읽기 전용 URL) | `/board/{code}` | 시각화 조회만 |
| **운영자 (Operator)** | 관리자 위임 | `/admin` | 진행 제어만 (문항 편집 불가) — *v2* |

## 3. 핵심 사용자 시나리오

### 시나리오 A — 행사 진행 전체 흐름

1. **[준비]** 관리자가 세션 생성 → 자동으로 6자리 코드 `A7K2Q9` 및 QR 발급
2. **[준비]** 문항 5개를 미리 등록 (단답형 3, 객관식 1, 척도 1)
3. **[개장]** 전광판 URL을 빔프로젝터에 띄움 → QR + 코드 + "참여자 0명" 표시
4. **[입장]** 참여자가 QR 스캔 → 닉네임(선택) 입력 → 대기 화면 진입
   - 전광판 참여자 카운터가 실시간 증가 (0 → 87명)
5. **[출제]** 관리자가 1번 문항 **"당신이 존경하는 분은?"** 의 `출제` 버튼 클릭
   - 참여자 화면: 대기 → **문제 화면으로 자동 전환** (0.5초 슬라이드 인)
   - 전광판: 문제 텍스트가 상단에 크게 표시, 하단은 빈 캔버스
6. **[응답]** 참여자가 "세종대왕" 입력 → `제출`
   - 참여자 화면: "제출 완료 ✓" + 다른 참여자 응답 수 표시
   - 전광판: **"세종대왕" 풍선이 팝(pop) 애니메이션과 함께 등장**
   - 같은 답변이 또 들어오면 → **기존 풍선이 부드럽게 커짐** (숫자 뱃지 2 → 3 → 12)
7. **[마감]** 관리자가 `마감` 클릭 → 참여자 입력창 비활성화, 전광판은 최종 레이아웃으로 정렬
8. **[반복]** 2번 문항 출제 → 위 과정 반복
9. **[종료]** 세션 종료 → 전체 결과 Excel/이미지 내보내기

### 시나리오 B — 지각 참여자
문항이 이미 출제된 상태에서 입장한 참여자는 **현재 활성 문항으로 즉시 진입**한다. (Hub 접속 시 서버가 현재 상태를 스냅샷으로 전송)

### 시나리오 C — 네트워크 끊김
참여자 Wi-Fi가 끊기면 SignalR이 자동 재연결(exponential backoff)하고, 재연결 시 현재 문항 상태를 재수신한다. 제출 중 끊긴 답변은 localStorage에 임시 보관 후 재전송한다.

### 4.3 문항 유형별 사양

#### ① 단답형 (Short Text → 워드클라우드/버블)
- 입력: 텍스트 1줄, **최대 20자**
- 옵션: 1인당 제출 개수 (1개 / 최대 3개)
- 정규화: 앞뒤 공백 제거 → 내부 다중 공백 축약 → 대소문자 통일 → 동의어 사전 치환
- 시각화: **버블 클라우드** (핵심)

#### ② 객관식 (Multiple Choice)
- 보기: 2~8개, 이미지 첨부 가능(v2)
- 옵션: 단일선택 / 복수선택, 정답 지정 여부(퀴즈 모드)
- 시각화: **가로 막대 그래프** — 실시간으로 막대가 늘어나며 %와 표수 동시 표기
- 퀴즈 모드 시: 마감 후 정답 보기에 초록 하이라이트 + 정답자 수 표시

#### ③ 척도 (Scale / Rating)
- 형식: 1~5 또는 1~10 슬라이더, 별점, NPS(0~10)
- 시각화: **대형 평균 숫자 + 분포 히스토그램 + 게이지 바늘 애니메이션**

#### ④ 자유서술 (Long Text)
- 입력: 여러 줄, 최대 300자
- 옵션: 익명 / 닉네임 노출 선택
- 시각화: **카드 스트림** — 새 응답이 아래에서 위로 떠오르며 흐르는 벽(wall) 형태
- 모더레이션 필수: 관리자 승인 후 노출 모드 지원

## 5. 전광판 시각화 설계 (핵심 차별점)

### 5.1 버블 클라우드 — 크기 산정 로직

같은 단어가 많이 나올수록 큰 풍선, 적게 나올수록 작은 풍선으로 표현한다.
빈도에 **선형**으로 반지름을 매핑하면 1등 단어가 화면을 다 잡아먹으므로 **제곱근 스케일**을 사용한다.

```
r(w) = r_min + (r_max - r_min) × sqrt( (c(w) - c_min) / (c_max - c_min) )

  c(w)   : 단어 w의 응답 빈도
  c_min  : 현재 화면 내 최소 빈도 (보통 1)
  c_max  : 현재 화면 내 최대 빈도
  r_min  : 32px  (최소 풍선 반지름)
  r_max  : 화면 짧은변의 18% (반응형, 최대 160px)
```

- `c_max == c_min` (모두 동일 빈도)일 때는 전부 중간값 `(r_min+r_max)/2` 적용
- 표시 상한: **상위 40개 단어**. 나머지는 `기타 N종` 소형 풍선으로 집계
- 신규 단어 등장: `scale 0 → 1.15 → 1.0` **팝(pop) 바운스** 250ms
- 기존 단어 증가: 반지름 보간 400ms `ease-out-back` + 짧은 흔들림, 숫자 뱃지 카운트업

### 5.2 레이아웃 알고리즘
- **d3-force** 기반: `forceCenter` + `forceCollide(r + 6)` + 약한 `forceManyBody`
- 매 갱신마다 전체 재배치하지 않고 **기존 좌표를 유지한 채 alpha를 0.3으로 재가열** → 화면이 튀지 않음
- 캔버스 이탈 방지를 위한 경계 제약 적용
- 대안(단순 구현): **d3-hierarchy `pack()`** 원형 패킹 — 물리 시뮬레이션 없이 안정적이나 재배치 시 이동량이 큼

### 5.3 비주얼 스타일

| 요소 | 사양 |
|---|---|
| 배경 | 딥 네이비 → 퍼플 그라데이션 (`#0F172A → #312E81`), 은은한 파티클 |
| 풍선 색상 | 5색 팔레트 순환 (`#38BDF8 #A78BFA #FB7185 #FBBF24 #34D399`) |
| 풍선 재질 | 반투명 채움 + 상단 하이라이트 원 + 부드러운 그림자 → *유리 풍선* 느낌 |
| 텍스트 | Pretendard Bold, 풍선 반지름에 비례한 폰트 크기, 자동 줄바꿈 |
| 빈도 뱃지 | 풍선 우하단 원형 뱃지, 빈도 2 이상일 때만 노출 |
| 유휴 모션 | 각 풍선이 3~5초 주기로 상하 2~4px 부유(floating) |
| 1위 강조 | 최다 득표 풍선에 은은한 글로우 링 + 왕관 아이콘 |

### 6.2 SignalR Hub 설계

**Hub: `LiveHub` (`/hubs/live`)**

그룹 구조 — 세션·역할별로 분리하여 불필요한 브로드캐스트 방지
```
room:{code}:participants
room:{code}:board
room:{code}:admin
```

**Client → Server**

| 메서드 | 파라미터 | 설명 |
|---|---|---|
| `JoinRoom` | `code, role, participantToken?, nickname?` | 입장. 응답으로 현재 상태 스냅샷 수신 |
| `SubmitAnswer` | `questionId, payload` | 응답 제출 |
| `OpenQuestion` | `questionId` | (admin) 출제 |
| `CloseQuestion` | `questionId` | (admin) 마감 |
| `RemoveAnswer` | `answerId` | (admin) 응답 삭제 |

**Server → Client**

| 이벤트 | 페이로드 | 수신 대상 |
|---|---|---|
| `StateSnapshot` | 현재 문항 + 현재 집계 | 신규 접속자 |
| `QuestionOpened` | `{ id, type, title, options, config }` | participants, board |
| `QuestionClosed` | `{ id, finalAggregate }` | 전체 |
| `AggregateUpdated` | `{ questionId, deltas[], totals }` | board, admin |
| `ParticipantCount` | `{ joined, answered }` | board, admin |
| `SubmissionAck` | `{ status, answerId }` | 제출한 본인만 |
| `AnswerRemoved` | `{ answerId, token }` | board |

### 6.3 브로드캐스트 스로틀링 ⚠ 핵심 설계

100명이 동시에 제출하면 초당 100회 브로드캐스트가 발생해 전광판 애니메이션이 깨진다.
→ **집계 버퍼 + 주기적 플러시** 방식을 채택한다.

```
[제출] → 서버 인메모리 집계 갱신(즉시) + DB 비동기 저장
              ↓
       변경분(delta) 버퍼에 누적
              ↓
   BackgroundService가 300ms마다 1회만 board 그룹에 브로드캐스트
```

- 브로드캐스트 최대 **초당 3~4회**로 고정 → 네트워크·렌더링 부하 예측 가능
- 클라이언트는 delta만 받아 부분 갱신 (전체 재계산 없음)
- 변경분이 없으면 전송 생략

### 6.4 배포 구성 (단일 인스턴스 기준)

```
[참여자 모바일] ─┐
[전광판 PC]     ─┼─ HTTPS/WSS ─→ [Kestrel + ASP.NET Core] ─→ [SQL Server]
[관리자 PC]     ─┘                        │
                                    (InMemory 집계)
```
> **주의**: 다중 인스턴스로 확장 시 SignalR **Redis Backplane**과 분산 집계 저장소(Redis)가 필수. 100명 규모에서는 단일 인스턴스 권장(비용·복잡도 최소).

## 8. 한글 단어 정규화 파이프라인 ⚠ 품질 핵심

"세종대왕", "세종 대왕", "세종대왕님", "SEJONG"을 하나로 묶지 못하면 워드클라우드는 의미가 없다.

```
① Trim + 다중공백 → 단일공백
② 유니코드 NFC 정규화
③ 특수문자·이모지 제거 (한글/영문/숫자/공백만 허용)
④ 영문 소문자 통일
⑤ 후행 존칭·조사 제거 : "님", "씨", "선생님" 접미 / "은|는|이|가|을|를"
⑥ 공백 제거본으로 2차 키 생성  ("세종 대왕" ≡ "세종대왕")
⑦ WordAliases 사전 치환
⑧ BannedWords 검사 → 마스킹 또는 차단
⑨ (선택) 편집거리(Levenshtein) ≤ 1 이면 후보 병합 제안 → 관리자 승인
```

- **DisplayText**는 가장 먼저 등장했거나 가장 빈도가 높은 원문 표기를 사용 (화면에는 자연스러운 형태로 노출)
- ⑨ 자동 병합은 오작동 위험이 있으므로 **v1에서는 관리자 제안 UI만** 제공

## 10. 화면별 상세 설계

## 부록 A. 버블 렌더링 의사코드

```javascript
// AggregateUpdated 수신 시
connection.on("AggregateUpdated", ({ deltas }) => {
  deltas.forEach(d => {
    const node = nodeMap.get(d.token);
    if (node) {
      node.count = d.count;                 // 기존 → 커짐
      node.targetR = radiusOf(d.count);
      node.bump = true;                     // 흔들림 트리거
    } else {
      nodeMap.set(d.token, {                // 신규 → 팝 등장
        token: d.token, label: d.display, count: d.count,
        x: cx + rand(-40, 40), y: cy + rand(-40, 40),
        r: 0, targetR: radiusOf(d.count), isNew: true
      });
    }
  });
  simulation.nodes([...nodeMap.values()]);
  simulation.force("collide").radius(n => n.targetR + 6);
  simulation.alpha(0.3).restart();          // 부분 재배치 (전면 리셋 X)
});

function radiusOf(c) {
  if (cMax === cMin) return (R_MIN + R_MAX) / 2;
  return R_MIN + (R_MAX - R_MIN) * Math.sqrt((c - cMin) / (cMax - cMin));
}
```
